# 순신 칼질이 약하고 끊겨 보이는 이유 (프레임 단위 조사, 2026-11-24)

사용자가 여러 판에 걸쳐 같은 말을 했다: "순신 칼질이 광개토·사임당보다 약하고 끊겨 보인다."
하데스 칼 연타와 우리 네 영웅을 같은 항목으로 재고, 순신만 다른 조건을 모두 꺼냈다.

이 문서는 보고서다. 값은 바꾸지 않았다.

박자는 PR #116을 기준으로 했다: 휘두르기 1.35배, 다음 타 0.334·0.349초.

**그림** (모두 `build/preview/`, 커밋하지 않음)

  - 한 칸 = 0.05초, 20칸 = 1초. 노란 테두리 = 칼이 닿은 칸, 파란 테두리 = 다음 타가 시작한 칸.
  - 줄 순서: 하데스 → 순신(#116 전) → 순신(#116) → 광개토 → 사임당 → 세종.
- `hades_sword_combo_30fps.png`
  - 하데스 1·2·3타를 30fps 칸마다 (66.600~67.967초).

**도구**

**순신만 다른 조건**
- 새 웹 동작이고, 구간이 길다: 원본 0.66~0.87초를 6칸에 담는다.
- 칸 시각에 맞닿는 칸 붙잡기가 들어 있다 (0.80 → 0.84, 1.33 → 1.37, 2.47 → 2.51).
- 휘두르기가 빨라져 있다 (1.35배).
- 칼 박힘이 있다. 칼 박힘이 걸린 동안은 3타 늦은 감속과 처치 멈춤이 꺼진다.
- 몹에 붙기와 돌진 타격이 있다.
- 전진이 가장 크다.

**잡몹 여럿을 한 번에 벨 때**
- 순신의 칼 박힘은 휘두름마다 한 번이라 겹쳐 길어지지 않는다.
- 광개토·사임당은 맞은 수만큼 멈춤이 0.01초씩 늘어 최대 0.08초가 된다.
- 기술 멈춤(GameTime)은 겹치면 더 긴 것 하나만 남는다.

## 3. 그림이 칸마다 얼마나 바뀌는가 (끊겨 보이는 이유)

구운 공격 시트에서 앞 칸과 다음 칸의 실루엣이 다른 픽셀 수를 셌다. 앞 칸 실루엣 넓이로 나누고, 8방향의 중앙값을 냈다.

| 영웅 · 동작 | 칸 사이 변화 (0→1, 1→2, 2→3, 3→4, 4→5) | 닿는 칸 → 다음 칸 |
|---|---|---|
| 순신 1타 | 0.51, 0.58, 0.30, **0.23**, 0.49 | **0.23 (줄어듦)** |
| 순신 2타 | 0.38, 0.30, 0.34, **0.31**, **0.80** | 0.31, 마지막 칸에서 **0.80 튐** |
| 순신 3타 | 1.16, 0.79, 1.09, **0.42**, 0.46 | 0.42 |
| 광개토 1타 | 0.33, 0.42, 0.52, **0.62**, 0.70 | **0.62 (커짐)** |
| 광개토 2타 | 0.80, 0.83, 0.67, **0.89**, 0.84 | 0.89 |
| 사임당 1타 | 0.16, 0.34, 0.33, **0.36**, 0.44 | 0.44 |
| 사임당 2타 | 0.38, 0.36, 0.33, **0.41**, 0.59 | 0.41 |

**광개토·사임당**
- 칼이 닿을 무렵 그림이 가장 크게 바뀐다. 칼이 몸을 지나 끝까지 휘둘러지는 것으로 읽힌다.
- 하데스도 같다: 닿는 칸에서 멈추지 않고 시간만 늦춘다.

**순신**
- 닿는 칸에서 변화가 오히려 줄어든다. 칸 시각을 일부러 붙잡아 두었기 때문이다 (#84, 웹 동작 구간도 같음).
- 바로 그 순간 칼 박힘 0.05초가 그림을 세운다.
- 그래서 닿고 약 0.1초 동안 거의 움직이지 않는다. 휘두름이 몸을 통과하지 못하고 칼이 멈춘 것처럼 보인다 = "약하다".
- 2타는 마지막 한 칸에서 자세가 크게 튄다 (0.80) = "끊긴다".

**구운 시트 몸 기울기** (`measure_motion.py`)

**정리**
- 지금 순신 1·2타 동작은 받아 둔 칼 동작 중 가장 크게 움직이는 축에 든다. 기울기·호가 광개토·사임당보다 작지 않다.
- 동작 폭보다 3절의 "닿는 칸 붙잡기 + 칼 박힘"이 먼저다.
- 바꾼다면 3타가 가장 약하다 (기울기 50°, 호 194°). 후보는 두 가지다:
  - web_weaponcombo 1.53~2.47: 호 412°, 크게 돌아 베기.
  - righthandswordslash: 호 319°.
- 새 동작이 필요해지면, Meshy 웹 라이브러리의 칼 연타(Sword combo)·크게 돌아 베기(spin slash)·두 손 내려베기 종류를 고른다. 몸통이 돌고 한 발 내딛는 것으로, 사용자가 웹에서 받아 두는 방식이라 크레딧 0이다.
  - 다만 위 결과로는 동작 교체가 필요하다고 보지 않는다.

## 5. 고치는 안 (세 단계)

### 1단계: 데이터만 (바로 가능)

| 안 | 값 | 기대 효과 | 우두머리 균형 |
|---|---|---|---|
| 칼 박힘 줄이기 | `BladeBiteData.stop_times` 0.05/0.05/0.10 → 0.02/0.02/0.06, `jitter_px` 2.5 → 1 | 닿는 순간 서 있는 시간이 절반 | 거의 없음 (몹이 조금 일찍 움직임) |
| 박힘 대신 하데스식 늦은 감속 | 1·2타 박힘 끄기 (stop 0), 3타만 박힘 | 휘두름이 몸을 통과, 3타만 무게 | 거의 없음 |
| 검기 크게 | 순신만 초승달 배율 (지금은 전체 공통 값 → 영웅별 값이 필요, 코드 몇 줄) | 하데스처럼 몸보다 큰 흰 호 | 없음 |

**함께 고칠 것 (코드 한 줄씩)**
- 칼 박힘 중에도 3타 늦은 감속은 건다 (`ImpactFx.melee_hit`).
- 처치 멈춤은 박힘이 끝난 뒤 건다.
- 그러면 순신도 광개토·사임당과 같은 "한 방" 박자를 얻는다.

### 2단계: 구간 다시 자르기 (크레딧 0, 굽기만)

칸 시각의 맞닿는 칸 붙잡기를 없애고 닿은 뒤 칸을 고르게 펼친다. 닿는 칸 번호(3)는 그대로라 피해 시점이 같다.
- 1타 `times` [0.33, 0.47, 0.73, 0.80, 0.84, 1.07] → [0.33, 0.50, 0.66, 0.80, 0.93, 1.07]
- 2타 [1.07, 1.20, 1.27, 1.33, 1.37, 1.73] → [1.07, 1.16, 1.25, 1.33, 1.53, 1.73]
  - 마지막 튐 0.80이 두 칸에 나뉜다.
- 3타 [1.73, 2.07, 2.27, 2.47, 2.51, 2.60] → [1.73, 2.00, 2.27, 2.47, 2.55, 2.60]

**바꿀 곳**
- `tools/ai3d/heroes/yi_sun_sin.json`의 `times`
- `data/live3d/yi_sun_sin.tres`의 같은 값 (3D)

**그 뒤**
- 다시 굽고 (`bake_sprites.gd --only=yi_sun_sin`) 3D 세션과 맞춘다.
- 기대 효과: 닿은 뒤 칸 변화가 광개토처럼 커져 휘둘러 지나가는 그림이 된다. 2타 끝 튐도 없어진다.
- 우두머리 균형: 없음 (닿는 시각·판정 같음).
- 1단계의 칼 박힘 줄이기와 같이 해야 효과가 크다.

### 3단계: 동작 교체 (필요할 때만)

- 3타만 web_weaponcombo 1.53~2.47(크게 돌아 베기)이나 righthandswordslash로 바꾼다.
- 닿는 시각이 바뀌므로 `combo_flow` 이어짐 시험, 사거리 시험, 3D 동기화가 필요하다.
- 우두머리 균형: 3타 닿는 시각이 바뀌면 순신 피해 흐름이 조금 바뀐다. 우두머리 세션과 같이 다시 잰다.

**권장 순서**
1. 1단계 (칼 박힘 줄이기 + 늦은 감속·처치 멈춤 되살리기)
2. 2단계 (칸 시각 고르게)
3. 사용자 판
4. 그래도 약하면 3단계 (3타만)
