## 4. 구조 대안

**30 MiB 는 어디서 온 제한인가**: Play 스토어가 아니라 **Claude 앱이 파일을 보내는 한도(SendUserFile 30 MiB)** 다. 이미 GitHub 비공개 draft 릴리스 직접 링크로 우회하고 있다.

| 길 | 30 MiB 문제 | 비고 |
|---|---|---|
| GitHub draft 릴리스 링크 (지금) | 해결됨 | 98 MB 도 문제 없음. 받는 시간만 늘어남 |
| **Play 내부 테스트 트랙 / 내부 앱 공유 (AAB)** | 해결됨 | 폰은 Play 에서 설치·자동 업데이트. Play 의 한도는 기본 모듈 다운로드 200 MB 라 지금 크기는 여유. Play Console 계정·앱 등록 필요. `build/play-aab` 브랜치·`export_aab.ps1` 기본값이 이미 AAB |
| AAB 분할 | 줄지 않음 | 이미 arm64 하나, 그림이 WebP 라 밀도·텍스처 형식 분할 이득 없음. AAB 에서 받는 크기 ≈ 지금 APK |
| Play Asset Delivery (설치 후 내려받기 팩) | 스토어 설치에서만 의미 | 음악·영상·이야기 그림(34 MB)을 fast-follow 팩으로 빼면 첫 설치가 그만큼 작아진다. 하지만 Godot 4.7 내보내기에 PAD 기본 지원이 없어 gradle 빌드 + 플러그인/직접 연결이 필요하고, 옆으로 설치하는(사이드로드) 시험 APK 에는 쓸 수 없다. 출시 직전에 검토 |

**"실시간 3D"로 그릴 때 용량** (live3d 시험 세션 `docs/research/live3d_spike.md` 수치 인용):
- 정리한 영웅 1명 = 메시 약 1.2 MB + 동작 0.3 MB + 텍스처 1024² ETC2 약 0.7 MB = **약 2.2 MB** (지금 시트 3.4~5.2 MB). 3D 를 다시 켠 엔진 **+4~6 MB**.
- 혼합 (영웅 4명만 3D): 시트 −16.3 + 3D +약 9 + 엔진 +4~6 → **거의 같거나 1~3 MB 감소**.
- 질문의 조건(모델 약 2만 면 + **2048²** 텍스처, 24개)을 그대로 넣으면: 텍스처 2048² ETC2(밉맵 포함) 약 2.7 MB + 메시 약 1.2 + 동작 0.3 ≈ **4.2 MB × 24 ≈ 100 MB + 엔진 5 MB** → 지금 스프라이트(28 MB)보다 훨씬 큼. 텍스처 1024² 면 약 2.2 × 24 ≈ 53 MB. 영웅 1024² + 적 512²·5~10k 면이면 약 4×2.2 + 20×1.0 ≈ **29 MB + 엔진 5 MB ≈ 지금과 비슷**. 즉 3D 는 텍스처 크기를 줄여야만 용량이 같아진다 (화면 키 190 px 라 512~1024 로 충분하다는 것이 시험 세션 판단).
- 3D 의 장점은 용량이 아니라 **동작·방향이 늘어도 용량이 안 늘어남** (지금은 동작 하나 = 영웅당 0.3~0.5 MB, 방향·칸 수에 비례).

## 5. 목표별 계획

고정 비용 (엔진 11.9 + 안드로이드 2.9 + 스크립트 등) ≈ **15 MB**. 그림·소리에 쓸 수 있는 몫이 목표에서 이것을 뺀 만큼.

| 목표 | 콘텐츠 몫 | 해야 할 것 | 포기할 것 |
|---|---:|---|---|
| **지금 유지 (약 95 MiB)** + 손해 없는 다이어트 → **약 80 MB (76 MiB)** | 65 | 안 1~5 + throw 제거 (−18.5 MB) | 거의 없음. 전달은 지금처럼 링크, 또는 Play 내부 테스트 |
| **50 MiB (52.4 MB)** | 37 | 위 + 칸 192(6) + 방향 5(8) + 음악 80k·구간 줄이기(11) + 글꼴 교체(12) | 왼쪽 볼 때 손 바뀜, 곡 반복, 글꼴 모양, 약간 흐린 확대 |
| **30 MiB (31.5 MB)** | 16 | 위 전부 + 무대당 음악 1곡 1분(64k), 여는 영상 삭제, 이야기 그림 절반 크기·장수 축소, 적 종류 공유, 칸 160 | 무대별 곡 구성·여는 영상·이야기 그림 품질, 적 다양성, 캐릭터 선명도. 사실상 "한 무대 데모" 수준. **추천하지 않음** |

추천: **지금 유지 + 손해 없는 다이어트(안 1~5)**, 시험 전달은 링크(또는 Play 내부 테스트). 30 MiB 는 앱 전송 한도라 콘텐츠를 깎아서 맞출 가치가 낮다. 방향 뒤집기(8)는 용량이 가장 크게 주는 안이지만 화면이 바뀌므로 사용자가 mirror 그림을 보고 정한다.

## 다시 재기

1. `tools/build/export_aab.ps1 -Apk -Out build/android/x.apk`
2. APK 의 `assets/.godot/imported/*` 크기를 각 `.import` 의 `path=` 로 원본에 이어 붙여 묶는다 (zip 의 compress_size).
3. 두 APK 비교는 파일 이름에서 `-<md5>` 를 지우고 같은 이름끼리 뺀다.
4. 쓰이는지: 원본의 `res://` 경로와 `.import` 의 uid 를 `scripts/ scenes/ data/ assets/` 의 .gd·.tres·.tscn 에서 찾는다 (`tests/test_export_excludes.gd` 가 제외 목록에 대해 같은 일을 한다).
