# 하데스 기준 버티컬 슬라이스: 순신 · 한산(왜군) · 왜군 지휘관, 약 2분 (2026-11-22)

방향: 4영웅·3군대·16기술을 넓게 70점으로 올리지 않는다. **한 조각을 95점으로** 만들고, 그 규칙을 나머지에 복사한다.
하데스에서는 **구조와 느낌만** 가져온다. 조작(한 손·탭 연타·플릭 대시), 그림, 캐릭터, 음악은 한얼 것이다.
이 문서는 비교와 작업 목록이다. 구현은 사용자가 고른 뒤에 한다.

- 기준 코드: art/enemy-rebake 22d062c (575/575).
- 표시: **[문서]** 공개 자료(주소) · **[스니펫]** 위키 검색 요약만 확인 (hades.fandom 본문이 막힘) · **[관찰]** 해 본 사람이면 아는 현상 · **[추정]** 실측 아님.

## 0. 요약

- 가장 큰 차이 셋:
  1. **화면의 적 수:** 하데스는 4~8, 한얼은 최대 30에 무리 이벤트 +16.
  2. **바닥과 캐릭터의 명암 대비:** 한산 바닥이 영웅보다 밝고 채도도 높다. 하데스는 그 반대다.
  3. **방·웨이브 박자:** 하데스는 웨이브 → 클리어 → 보상 → 다음 방. 한얼은 150초 동안 이어 나오다 보스.
- 이 셋은 **코드와 데이터만으로** 바꿀 수 있다. 크레딧도 새 시스템도 필요 없다 (웨이브 박자는 기존 스포너에 규칙을 더하는 정도).
- 추천 순서:
  1. 명암 대비
  2. 밀도와 웨이브
  3. 예고 규칙 통일
  4. 보스 페이즈
  5. 끝맺음 박자 (마지막 처치 슬로우, 음악 북 빠짐)
  6. 그림 교체 (사용자 GPT)
- 단계마다 폰으로 확인한다.

## 2. 차이마다 한얼 식으로 맞추는 법·비용

비용 표시: **[코드]** 코드만 · **[데이터]** 데이터만 · **[그림]** 새 그림 (사용자 GPT) · **[Meshy]** 크레딧 · **[P0 밖]** 새 시스템.

### 2.1 몹 밀도: 적게, 하나하나 읽히게 [데이터 + 코드 조금]
제안 값 (슬라이스 한산만, 다른 무대는 나중에 복사):
- **화면 상한:** `max_alive` 30 → **8**, 무리 이벤트는 슬라이스에서 끔 (`horde_enabled` false).
- **웨이브 3번 + 보스:** 웨이브마다 병사 4~5 + 조총 1~2, 셋째 웨이브에 중장 1.
  - 다음 웨이브는 남은 적이 2마리 이하일 때 나온다.
  - 정예는 둘째 웨이브 끝에 1번.
  - 지금 스포너의 시간표(`unlock_times`·`elite_times`)를 "웨이브 목록 + 남은 수 조건"으로 바꾼다. [코드: 스포너에 웨이브 모드, 새 Resource `WaveData`]
- **등장 예고:** 스폰 자리(영웅 둘레 260~420px, 화면 안)에 먹 번짐 원을 0.6초 보인 뒤 나타난다. 그동안은 공격하지 않는다. [코드, 기존 ring 그림 재사용]
- **적이 적어진 만큼 하나하나 단단하게:**
  - 병사 30 → **45** (3타 연계 한 번 + 1타, 손 연타면 마무리 한 번으로 정리)
  - 조총 20 → 25
  - 중장 140 그대로 (슈퍼아머 + 경직이 역할)
  - 정예 520 → 400 (슬라이스 길이)
- **피해:** 한 방 = 체력의 10~25%로 정리. 병사 20 그대로, 조총 12, 중장 35 → **25**, 정예 40 → **30**, 보스 30~35 → 25~30.
  - 근거: 하데스 6~28%. 한얼 쪽 적이 적으니 한 방 무게는 남기되, 30% 넘는 한 방은 없앤다.
- **150초 → 웨이브 3번(각 약 25초) + 보스 약 50초 = 약 2분.**
  - 경험치 레벨업 인장은 웨이브 끝마다 1번으로 묶는다 (아래 2.3).

위험: 적이 적으면 자동 평타만으로 너무 쉬워질 수 있다. 근접 우선·탭 연타 마무리·반격이 손맛의 중심이 되도록, 폰 확인 때 "손 안 대고 버티기"가 실패하는지 본다.

### 2.2 밝은 종이 바닥에서 타격 효과가 묻힘: 해결안 셋
| 안 | 내용 | 비용 | 장단점 |
|---|---|---|---|
| **A. 바닥 명도·채도 낮추기 (추천)** | 배경 그림에 무대별 `floor_tint` 곱하기 (예: 명도 ×0.72, 채도 ×0.6)와 가장자리 비네트. 목표는 바닥 평균 명도 0.36·채도 0.2 이하 (지금 0.51·0.37) | [데이터 + 코드 한 줄] | 효과·캐릭터·예고가 한꺼번에 산다. 수묵 종이 느낌은 비네트와 얼룩으로 유지 |
| B. 효과에 먹 외곽선 | 붓 불꽃·초승달·숫자에 먹 테두리 패스 (셰이더 또는 두 번 그리기) | [코드] (스킬 연출 파일은 스킬 고도화 세션과 맞춤) | 하데스식 굵은 먹선과 같은 원리. 그리는 비용이 조금 늘어난다 |
| C. 영웅색 진하게 | `swing_color`·불꽃 색을 채도↑·명도↓ (순신 0.45,0.8,1 → 0.15,0.45,0.85), 흰 불꽃은 영웅색으로 | [데이터] | 가장 싸다. 단독으로는 부족하고 A와 함께 쓴다 |

추천: **A + C를 먼저**, B는 스킬 그림을 교체할 때 같이.

### 2.3 방·웨이브 박자와 끝맺음 [코드]
- 웨이브 마지막 적 처치: 짧은 슬로우 0.25초 (기존 finisher 규칙 재사용), 음악 **북 층 끄기**(곡 stem이 있으면), 그다음 성장 인장 3장.
- 인장 고르기는 웨이브 사이 숨 고르기로 쓴다. 지금의 레벨업 즉시 고르기 대신 "웨이브 끝에 쌓인 레벨만큼".
- 문 고르기·방 이동은 **[P0 밖]**. 슬라이스는 한 무대 안 웨이브로 대신한다.

### 2.4 적 공격 예고 규칙 통일 [데이터 + 코드 조금]
한 문장 규칙: **"적이 붉은 먹으로 바닥에 칠한 곳은 0.6초 뒤 맞는다. 칠이 진해지다 마지막 0.15초에 번쩍하면 지금이다."**
- 모든 예고는 최소 0.6초 (병사 0.5 → 0.6). 마지막 번쩍임(`strike_flash_from`)은 모든 적에서 같은 비율로.
- 예고 소리(`e_windup`)는 모양과 무관하게 한 종류. 중장·보스만 낮은 겹.
- 색은 인주색 하나 (이미 그렇다). 보스 전용 색은 쓰지 않는다 (하데스는 보라를 썼지만, 한얼은 하나로 단순하게).
- 조총의 선 예고와 찌르기의 직사각형도 같은 채움 → 테두리 → 번쩍 순서로.

### 2.5 보스 페이즈 (왜군 지휘관) [데이터 + 코드]
- 체력 600 → **1400** (보스전 약 50초, 3타 연계·마무리·기술 기준).
- **1페이즈 (100~66%):** 부채 휘두르기 + 돌진 (지금 공격 2개).
- **2페이즈 (66%):** 짧은 무적 + "鼓" 북소리, 조총병 2 + 병사 2 호출, 큰 원 내려찍기 추가.
- **3페이즈 (33%):** 호출 한 번 더, 순환 간격 0.6 → 0.4.
- 경직 게이지(22% ×2.0)는 그대로 둔다. 페이즈가 바뀌면 경직 게이지를 채운다.
- 코드: `EnemyAttackData.patterns`를 페이즈 목록 `BossPhaseData`로 (새 Resource, 작음). 호출은 기존 스포너 재사용.

### 2.6 그대로 못 가져오는 것 (한 손 조작)
- **대시 공격:** 하데스는 대시 중 공격으로 무적이 끝난다. 한얼은 대시 직후 탭 = 파도격(기술)이라 이미 따로 있다. 그대로 둔다.
- **공격 회복을 대시로 끊기:** 이미 플릭이 언제나 이긴다 (확인만).
- **문 고르기·방 이동:** 세로 한 손 화면에서 문까지 걷는 것은 손이 많이 간다. 슬라이스에서는 웨이브로 대신한다 [P0 밖].
- **캐스트(탄 꽂기)·특수기 버튼:** 없다. 한얼은 제스처 기술 3개가 그 자리다.

## 3. 2분 슬라이스 "완성" 정의 (체크리스트)
- [ ] 바닥이 캐릭터보다 어둡고 채도가 낮다 (바닥 명도 ≤ 0.36, 순신·왜군 테두리가 늘 읽힘). 폰 밝기 50%에서 확인.
- [ ] 화면 적 ≤ 8. 적마다 무엇을 하는지 1초 안에 읽힌다 (병사 = 찌르기, 조총 = 선, 중장 = 원).
- [ ] 웨이브 3번 + 보스, 전체 2분 ±20초. 등장 예고 0.6초 동안은 맞지 않는다.
- [ ] 모든 적 예고가 같은 규칙 (붉은 칠 → 진해짐 → 번쩍 → 맞음, 최소 0.6초, 같은 소리).
- [ ] 한 방 피해 10~25%, 30% 넘는 한 방 없음.
- [ ] 탭 연타 1·2·3 → 마무리, 반격, 대시가 2분 안에 각각 여러 번 나온다. 손을 안 대면 진다.
- [ ] 웨이브 끝: 슬로우 + 북 빠짐 + 인장 3장.
- [ ] 보스 3페이즈, 페이즈마다 새 공격 하나 + 호출. 처치 슬로우 + 확대 + 승리 곡.
- [ ] 해룡참·파도격·해일검기·반격 그림이 새 그림 (아래 목록).
- [ ] 60fps 유지 (중급 폰), APK 30MiB 이하 목표는 따로 (지금 80MiB).

## 4. 작업 순서 (단계마다 폰 확인)
| 단계 | 할 일 | 비용 | 폰에서 볼 것 |
|---|---|---|---|
| 1 | 바닥 명도·채도 낮추기 (A) + 영웅색 진하게 (C) | 데이터 + 코드 한 줄 | 캐릭터·효과·예고가 바닥에서 뜨는가, 수묵 느낌이 남는가 |
| 2 | 밀도·웨이브 (상한 8, 웨이브 3, 등장 예고), 체력·피해 재조정 | 코드 (WaveData) + 데이터 | 적 하나하나가 읽히는가, 지루하거나 너무 쉽지 않은가, 2분 길이 |
| 3 | 예고 규칙 통일 (최소 0.6, 번쩍 비율, 소리 하나) | 데이터 + 코드 조금 | 처음 보는 사람이 피할 수 있는가 |
| 4 | 웨이브 끝맺음 (슬로우·북 빠짐·인장 묶기) | 코드 | 숨 고르기가 생겼는가 |
| 5 | 보스 3페이즈·호출·체력 | 코드 (BossPhaseData) + 데이터 | 50초 보스전의 기승전결 |
| 6 | 스킬 그림 교체 (사용자 GPT) + 효과 먹 외곽선 (B) | 그림 + 코드 (스킬 고도화 세션) | 기술이 바닥에서 읽히는가 |
| 7 | 전체 다듬기 (소리 층·숫자 합치기·APK 크기) | 코드 | 처음부터 끝까지 한 판 |

Meshy 크레딧은 이 순서에 필요 없다. 보스 페이즈 전환 자세가 필요하면 그때 1~2클립(3~6크레딧)을 제안한다.

## 5. 필요한 그림 목록 (사용자 GPT, docs/skill_vfx_sheets.md B안)
- 해룡참 (탭 마무리): 물결 고리 + 용 머리 (위에서 본 고리, 투명 배경, 흰색에 가깝게 그려 영웅색을 곱함)
- 파도격 (대시 직후): 관통 물결 띠 3단
- 해일검기 (충전): 앞으로 뻗는 큰 파도 띠
- 반격 (회피 후): 넓은 원형 베기 + 물보라
- 등장 예고용 먹 번짐 원 (적이 나타날 자리), 1장
- 보스 페이즈 전환용 북·깃발 낙관, 1장
- (선택) 바닥 비네트·얼룩 그림 1장. 코드로도 만들 수 있다.

## 6. P0 범위를 넘는 것 (따로 표시)
- 방 사이 문 고르기, 보상 종류 미리보기 (하데스 문 아이콘)
- 갑옷 막대를 일반 적까지 넓히기 (지금은 정예·보스만)
- 대화 초상과 보스 대사 장면
- 음악 stem 층 (북 켜고 끄기): 곡 4개 계획에 들어가 있다. 슬라이스에서는 stem이 있는 곡 하나로 시험한다.
- 피해 숫자 합치기 (빠른 연타를 한 숫자로)
