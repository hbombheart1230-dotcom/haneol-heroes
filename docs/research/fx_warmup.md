# 효과 첫 사용 멈칫 (예열)

요청: 스킬·평타 효과를 처음 쓸 때 0.5초 안팎 멈칫 (3D 세션 PC 측정: 평타 2·3타 ~535ms, 충전 ~650ms, 해룡참·대시 가끔 ~530ms).

## 재는 법

`tools/perf/first_use_perf.gd` — 실제 main 장면에서 평타 1·2·3타(손 탭), 탭 마무리, 대시·충전·반격 기술, 처치를 한 번씩, 각 동작 뒤 40프레임의 최대 프레임(ms). 같은 차례를 한 번 더 해서 두 번째와 비교. `nowarm`으로 예열을 끄고, `skip=sheets,shapes,flow,draw`로 예열 부분을 하나씩 빼서 원인을 나눈다.

```
godot --path . --resolution 720x1280 -s res://tools/perf/first_use_perf.gd -- <무대 id> <영웅 id> [nowarm | skip=…]
```

## 원인 (효과별)

큰 프레임의 그리기 CPU 시간(`viewport_get_measured_render_time_cpu`)은 늘 2ms 안팎이었다 → PC에서는 셰이더·텍스처가 아니라 스크립트 쪽 첫 일이다. 빼 보기(skip)로 확인:

| 동작 | 원인 | 고침 |
|---|---|---|
| 순신 충전 (해일검기 물결) ~300ms | 물결 재질 `Projectile.flow_material()`이 처음 불릴 때 이음매 없는 잡음 텍스처(NoiseTexture2D)를 만든다 | 예열에서 미리 만든다 (`skip=flow`면 그대로 ~275ms) |
| 반격 (컷인 있는 기술, 네 영웅) +20~35ms | 컷인 기술 이름이 크게 찍혔다 줄어드는 동안 글꼴 크기가 프레임마다 바뀌어 크기마다 글자 그림을 새로 만든다 | 글꼴은 `cutin_font_px` 하나로 그리고 크기는 늘려 그린다 (`SkillCutin.draw_name`), 예열에서 같은 함수로 이름을 미리 그린다 |
| 세종 넷째 탭 (정음진) +40~70ms | 고리 글자가 써질 때 1.7배→1배로 글꼴 크기가 바뀐다 | 글꼴 46px 하나, 크기는 늘려 그림 (`OrbitGlyphs.GLYPH_PX`) |
| 세종 평타 글자 터짐 | 맞을 때 글자가 커지며 새 글꼴 크기 | 탄 글자 크기 그대로 늘려 그림 (`RangedFxLayer`) |
| 사임당 마무리·3타 등 +20~50ms | 시트 자르기(`VfxSheets`: 압축 풀기 + 장마다 텍스처), 코드로 만드는 입자 그림(`VfxTextures`, 픽셀마다 계산), 늦게 불러오는 효과 설정(`…Data.get_default`) | 예열에서 미리 |
| 셰이더 갈래·텍스처 첫 그리기 | PC 드라이버는 셰이더 캐시가 있어 차이 작음. 폰(GLES3)은 첫 컴파일이 클 수 있다 | 예열에서 모은 그림을 재질 갈래(그냥·더하기 빛·ink_decal·ink_vfx·enemy_rim) × 사각형·다각형·선으로 거의 투명하게 2프레임 그린다 |

소리 첫 재생은 따로 나눠 재지 않았다: 위 고침 뒤 남은 첫 사용이 두 번째 사용과 같은 범위라 크게 남은 것은 없다.

## 무엇을 예열하나 (데이터에서 자동)

`FxWarmup.collect`가 시작점에서 자원 그래프를 따라 내려가며 모은다 — 손 목록 없음:
- 시작점: 영웅(`HeroData` → kit 기술 넷 → 효과·그림, 평타 데이터), 무대(`StageTheme` → 물결·적 표·정예·보스 → 적 효과), 효과 설정(`CombatFeelData`, `RangedFeelData`, `DeathStyleData`, `BrushFlickData`, `SkillHitFeelData`, `SkillStageFeel`).
- 모으는 것: 그림(Texture2D, 몸 시트 SpriteFrames와 잡음 텍스처는 뺌), 기술 효과(SkillVfxData), 탄 시트(`<이름>_sheet` + `<이름>_sheet_grid` 규칙), 기술 이름.
- 새 기술·적을 데이터에 넣으면 자동으로 들어간다 (`tests/test_fx_warmup.gd`).

언제: `main.begin_run` (무대를 입힌 직후, 무대 제목 띠 동안, 첫 물결 0.5초 전). 효과 계층(2D)만 건드려 3D 영웅·보스에서도 같다.

## 측정 (PC, 다른 세션이 Godot을 함께 돌리는 중이라 잡음 있음; 각 2번, 최대 ms)

| 영웅 | 동작 | 전 | 후 |
|---|---|---|---|
| 순신 | 충전 | 306 / 307 | 17 / 22 |
| 순신 | 반격 | 43 / 31 | 21 / 22 |
| 순신 | 대시 기술 | 28 / 34 | 21 / 25 |
| 광개토 | 반격 | 57 / 44 | 24 / 29 |
| 세종 | 넷째 탭 마무리 | 70 / 98 | 29 / 27 |
| 세종 | 반격 | 56 / 45 | 29 / 27 |
| 사임당 | 넷째 탭 마무리 | 72 / 18 | 17 / 18 |
| 사임당 | 3타 | 50 / 50 | 32 / 31 |
| 사임당 | 반격 | 48 / 45 | 25 / 26 |

두 번째 사용(이미 데워진 상태)은 전에도 17~35ms. 한 번씩 튀는 값(전: 순신 2타 두 번째 사용 451ms, 후: 세종 1타 132ms 한 번)은 같은 동작 다른 회차에선 안 나와 함께 돌던 다른 프로세스 탓으로 본다.

3D 세션이 잰 ~530ms 평타 멈칫은 이 PC 2D 측정에선 재현되지 않았다 (평타 1·2·3타는 전에도 20~50ms). 폰에서 다시 재야 한다.

## 로딩 비용

- 예열 준비(모으기·시트·입자 그림·잡음): PC 130~170ms.
- 그리기 한 번이 든 프레임: 로딩 중 최악 프레임 1.0~1.5초 → 1.6~2.1초 (+0.4~0.6초). 무대 제목 띠 동안이라 판 중 멈칫이 로딩으로 옮겨 간 것. 폰은 더 길 수 있다.
